# AIENG 项目方向评估

日期：2026-09-06。范围：当前工作区的定位文档、近期 Git 历史、验证工作流，以及在线 MCP 实例的一次项目抽查。本文是建议，不是已批准的路线变更。

## 结论

**值得继续，但应该从“不断扩充 CAD/CAE 能力的平台”收敛成“面向简单机械零件、可复核的参数迭代工具”。下一阶段先验证可靠性和用户价值，不再以新增工具数、阶段数或演示模型数衡量进展。**

建议对外只承诺一个任务：

> 对一个有明确尺寸、载荷和约束的支架或安装件，完成建模、参数修改、重新分析，并交付能追溯到几何版本和求解记录的前后对比。

暂以个人或小团队、尚未建立稳定外部用户群为资源假设；团队规模、收入和真实用户数据尚未提供。若已有付费用户，其重复任务应优先于本文选择的场景。

## 一、现在究竟处于什么阶段

### 1. 已有可以保留的工程资产，不宜推倒重来

- 当前 MCP 服务可响应，onboarding 报告注册了 100 个工具，项目列表返回 50 个项目。这证明服务和历史项目存在，不证明每个工具都可靠，也不证明有 50 个用户。
- 当前架构已经把外部 agent、执行后端、几何内核、求解器和 `.aieng` 证据包分开。适合继续沿用，而非重新加入一个内置聊天代理层。依据：[README](../README.md)、[活动路径](architecture/active_paths.md)。
- 仓库已有真实 CalculiX 验证工作流与解析基准入口，而不只有截图和模拟数据。但本次未运行测试，也未检查远端 CI 结果，不能把“有验证门禁”说成“当前版本全部通过”。依据：[验证工作流](../.github/workflows/real-ccx-verification.yml)。
- 可信度分层明确区分求解完成、数值解析、目标比较和工程审核。这是有价值的设计原则，但还必须证明所有入口和旧项目都执行同一套规则。依据：[CAE 可信度](cae-credibility-ladder.md)。

**判断：已经超出概念演示，但尚没有足够证据把它视为经过外部用户验证的稳定产品。**

因此，不建议把下一季度继续投入横向功能扩张。先把这些修复提升为跨入口的端到端验收规则，而非只为单个事故补回归测试。

### 3. 当前抽查仍能看到状态解释不一致

只读抽查 `363b043f5728`（Dogfood Motor Mount）：

- `cae.results_available=false`，但 `artifact_detection.has_results=true`，且存在完成的历史求解记录及解析指标。
- `cad.last_edit` 报告 `collateral_change`，涉及非目标零件 `base_plate`。
- 网格旧元数据用整体 29.4 mm 尺寸解释“最薄处”并给出 reliable；当前项目指南已经明确指出这种口径过于乐观，应按最薄实体评估。
- 缺少设计目标，无法判断数值结果是否满足实际任务。

不能据此断言求解失败，或把一个历史测试包的问题推广到全部项目。不同结果字段也可能分别表示“汇总存在”和“场数据可展示”。但它说明：**旧包、兼容读取和不同消费端的状态口径，仍是需要验证的产品风险。** 一个 agent 或用户不应自己猜测哪个布尔值代表什么。

优先调查：定义各字段语义；以几何版本、求解 run ID 和证据文件明确关联；把旧评估标成 legacy/unknown 或显式重评估，不能直接沿用旧 reliable 标签作为新版本背书。

### 4. 文档已出现方向漂移

[2026-05-19 执行计划](copilot_direction_curated_plan.md)已经提出“不要增加孤立能力，先闭合参数修改—CAE—比较”，但具体方案仍围绕旧 UI 与 FreeCAD。当前 [CAD adapter 策略](cad_adapter_strategy.md)仍称 FreeCAD 是唯一接入后端，与当前活动路径不一致。

这不是单纯文字整洁问题：用户和 agent 都会把旧文档变成错误行动。建议保留历史记录，但明确标注历史状态；让一个短小的当前路线页成为唯一执行入口。本文不自动修改这些文件。

## 二、该选哪条路

| 路径 | 适合当前程度 | 关键判断 |
|---|---|---|
| 通用自然语言 CAD/CAE 平台 | 低 | 任务面过宽；每增加一种物理、几何或适配器，都扩大验证矩阵 |
| 简单机械零件的可复核参数迭代 | 高，建议先试 | 与已有参数编辑、求解、证据包最接近，容易设计可比较的完整任务 |
| 纯 `.aieng` SDK/证据基础设施 | 中，保留备选 | 架构可复用，但尚缺其他团队主动采用的证据；格式本身不是用户收益 |
| 研究/教学基准工具 | 中，取决于目标 | 可围绕工程 agent 的失败检测和状态一致性开展评估，但系统集成不能直接充当论文创新 |

外部背景：Onshape 已提供 CAD/PDM 问答助手，Fusion 已提供带几何、性能和制造约束的生成式设计。这不是同类端到端性能比较，也不能证明 AIENG 没有市场；它只说明“AI + CAD”或“可以优化”本身不足以定位。来源：[Onshape 官方](https://www.onshape.com/en/features/ai-advisor)、[Fusion 官方](https://help.autodesk.com/view/AGD/ENU/)。

更值得验证的差异是：**使用用户自己的 agent，在可控执行环境里，把一次工程修改变成可重放、可对比、能发现失效证据的交付物。** 这是潜在差异，不是已经成立的护城河。

## 三、接下来六周：只验证一个完整任务

以下数字是建议的试验门槛，不是已取得结果，也不是统计显著性标准。

### 第 1–2 周：建立一个可信的发布切片

选择一个单体安装支架：限定线性静力、小变形、明确材料与边界条件、少量可编辑参数。避免先引入螺栓预紧、接触、复杂装配或自由曲面重建。

验收链：

1. 新环境安装、连接 MCP。
2. 建立或打开参数化模型，核对载荷与约束。
3. 获得基线求解记录和指标。
4. 修改参数；保留基线，显式标记旧证据的适用性。
5. 再求解，对比质量、位移、应力与用户目标。
6. 导出包，重新打开，仍能解释哪个版本、哪个 run 支持哪个结果。

必须包括失败路径：缺少求解器、无效参数、拓扑绑定丢失、求解失败、旧包读取。失败不得转成成功；不能仅验证“输出字典包含某个键”。用一个材质或几何布局明显不同的第二案例检查通用性。

范围内的真实 CAD→网格→求解验证必须实际执行，跳过不得计入通过。数值验收使用适用的解析参考与网格收敛证据，不把一次求解完成当作工程正确性。

### 第 3–4 周：与朴素方案公平比较

找 3–5 位非作者使用者，其中至少包括有基础 CAE 经验的人。让他们完成同一项真实任务，不预先口述所有工具调用。

比较两条路径：

- 当前工作台；
- 同一 agent/model 配合 build123d、求解脚本和普通输出目录，不经过 AIENG 证据层。

固定任务、硬件、初始模型、载荷、目标和模型预算。记录总耗时、人工介入次数、失败恢复时间、结果追溯是否成功；安装时间单列，不能隐藏。

核心问题不是“能不能生成 STEP”，而是：**为闭环和证据层付出的复杂度，是否换来更少操作、更少错误或更容易复核？** 如果朴素脚本同样快、同样可靠，优先简化产品，而不是补充宣传词。

### 第 5–6 周：根据使用结果决定是否加码

建议继续投入的最低信号：

- 5 位试用者中至少 4 位不改源码即可完成限定流程；需要作者救援的步骤全部记账。
- 至少 2 位用户愿意带着第二个不同零件回来，而非只称赞演示。
- 状态丢失、静默错绑、失败冒充成功等关键场景没有未解决阻断项。
- 相对朴素基线，在耗时、介入或复核能力上出现可重复优势。不要只报成功案例的平均值。

未达标时：安装问题就收敛交付；交互问题就简化入口；证据层受欢迎但 UI 不受欢迎，就转 SDK/MCP runtime；始终没有重复需求，就降低产品化投入，保留为研究/教学工具。六周不是强制停项期限，而是避免无限扩张的一次决策检查点。

## 四、现在明确不做什么

- 不新建自己的大模型聊天平台，不与外部 agent 重复编排。
- 不同时推动 CFD、多商业 CAD 适配器、复杂装配物理和自由曲面重建。
- 不删除已有实验能力，但降低其默认入口和公开承诺等级。
- 不把 `.aieng` 宣传成已经被行业接受的标准；先证明交付与重新打开的价值。
- 不用内部测试项目数量、工具数量、测试总数替代用户成功率。
- 不把“可信度标签齐全”当作“结果可信”；必须有可核验的执行证据。

## 五、具体开发优先级

1. **P0：统一状态语义和版本关联。** 把包是否存在、求解是否完成、指标是否解析、场是否可展示、结果是否适用于当前几何分别定义，不允许含混的 success 吞掉拒绝或失败。
2. **P0：发布流程的真实端到端验收。** 从用户入口开始，直到导出重开，而非只有内部函数测试。
3. **P1：缩短 agent 的默认路径。** 100 个工具是能力面，不是新用户操作指南。按任务给出少量首选调用及失败恢复，保留低层工具供诊断，不急着重新发明抽象层。
4. **P1：清理当前文档入口。** 历史路线和旧架构标明状态，消除相互矛盾的执行建议。
5. **P1：形成统一前后对比交付。** 包含尺寸变更、目标达成情况、网格局限、几何版本和求解来源；缺证据就写 unknown。
6. **P2：仅由第二次真实使用暴露的新需求驱动扩展。** 不从“还有什么技术可以接进来”反推路线图。
